Founder's take

창업가라면, 어디서 돈이 나오나

가장 빠른 현금 · 대중 스케일 사주 > 팬덤 글로벌 결제 + 검증된 앱 comps(점신·포스텔러)가 운세앱 수익화를 이미 입증.
가장 깊은 해자 · 큰 계약 지방소멸 > 축제 B2G, 제도(기금·감사)가 강제 수요를 만든다. 단 세일즈 사이클 길고 시장 좁다.
리스크 조정 1위 사주 × 과제3 소비자 스케일 + 인바운드 결제력 + 정책 명분을 동시에. B2C로 빠르게 수익 내고, B2G(지자체 스폰서)로 확장하는 이중 경로가 열린다.

Product thesis

기획 코어 — 무엇을, 누구를 위해, 왜

타깃 = 방한 예정 글로벌 K팬. 가치 = 하나의 여정에 세 레이어(유입→결정→전환). 이 토대 위에서만 사주·K-Star·구축이 정당화된다.

Problem

문제 정의 (과제 3, 우리 언어로)

공고의 과제 3

  • K-콘텐츠·아티스트 관광 인프라의 수도권 편중
  • 글로벌 팬덤의 지방 도시 방문·탐방 편의성 미흡

진짜 문제 (우리 진단)

  • 방한 예정 K팬은 갈 마음은 있으나 수도권 밖 '어디'를 정할 근거가 없다
  • 지방을 "나와 상관있는 곳"으로 느낄 개인적 연결고리가 없다 → 그래서 서울에 머문다
  • 가설: 개인화된 "너만의 이유"를 주면 지방 방문 의사결정이 열린다

The core mechanic

용신(用神) 엔진

경쟁자(사주여지도 등)가 머문 "제일 강한 원소 = 지역" 매칭을 넘어, 부족한 오행을 채우는 처방으로 격상. 추천에 서사와 정당성이 생긴다.

생년월일시 → 사주 8글자 오행 분포 → 용신 도출(부족·필요 오행) → 자연·활동·음식 처방 → KTO 웰니스·관광 데이터

단순 성격 분류가 아니라 불균형을 진단하고 여행으로 회복시키는 웰니스 서사. 웰니스는 결제의사가 높고 공유·바이럴이 강하다.

"Your chart runs low on Water — restore balance in Gangwon's valleys and the East Sea."

The IP

오행 → 권역·테마 매핑

용신(채워야 할 오행) 기준. 전통 방위색(오방색)으로 코딩. "왜 이 지역인가"가 사주 논리로 설명되는 게 서비스의 핵심 자산이다.

근거(자의적 매핑 아님): 방위 배정은 표준 명리 — 목=東·화=南·토=中·금=西·수=北. 결정적으로 풍수지리에 "사람의 사주팔자가 땅의 오행과 상생이어야 길하다"는 이론이 실재한다(한국민족문화대백과). 즉 용신(부족 오행)을 그 오행의 방위·지역으로 채우는 건 명리·풍수 전통에 근거한다. 선례: 사주산(부족 오행 산 추천)·사주여지도.

The point

스타 매칭 → 여행으로 회수

스타 매칭이 순수 운세로 새지 않도록, 반드시 KTO 지역 데이터로 여행을 회수한다. 이것이 여행 미션을 희석하지 않고 오히려 지방 분산을 가속하는 장치다.

Build & risk

작동 방식 · 리스크

작동 방식

  • 스타 명식 DB — 공개 생년월일 50명(MVP) 사전계산
  • 생시 미상 처리 — 연·월·일주 3주(75%) 오행으로 산출, '시간모름' 옵션(임의입력이 오히려 부정확) + 경도·서머타임 보정
  • 트윈 일간 일치+오행 유사도 / 궁합 천간·지지 합·상생 간이규칙

리스크 대응

  • 법적(최대 급소) — 초상권·성명권·개인정보 → 아래 "심사위원 보완" 참조
  • 순수 운세앱화 방지 → 스타 고향을 KTO 지역 데이터로 반드시 회수
  • 정확도 논란 → "재미·문화체험(한국식 MBTI)" 포지셔닝

Strict triage

기능 확정 — 엄격 판단 & 구현

개발기간 2개월·소규모 팀·심사 구현성(완결성·구동 안정성) 30점 기준으로 냉정하게 컷했다. 기능 수보다 "핵심 논지를 end-to-end로 흠결 없이" 구현하는 게 승산이 크다. MUST만 만들고 나머지는 과감히 로드맵으로.

심사위원 관점 — 보완한 급소 5

공모전 심사위원(구현성·기획력·데이터활용·시의성)이 물고 늘어질 지점을 자료조사로 실측해 보완했다. "감점 요인을 먼저 제거"하는 게 상위 3팀 진입의 열쇠.

급소원래 약점보완 (근거)
웰니스 API 과장 "우수웰니스 88선을 API 직결" — TourAPI 15종엔 웰니스 전용 API 없음 정정 — 웰니스 88선 공개목록을 seed로 TourAPI 키워드검색·위치기반 연동. TourAPI를 아는 심사위원 대비.
매핑 자의성 "왜 火=남해?" 근거 없어 보이면 독창성이 아니라 감점 풍수 이론 "사주가 땅의 오행과 상생이어야 길하다" 실재(민족문화대백과) + 표준 방위 배정 → 근거 있는 독창성으로 격상
아이돌 생시 미상 "생시 없이 사주 되나?" 연·월·일주 3주=75% 오행이면 성격·오행 분석 성립. '시간모름' 옵션이 임의입력보다 정확(업계 표준).
유명인 법적 리스크 실명·생년월일·이미지 = 초상권·성명권·개인정보보호법 위반 소지 (가장 큰 급소) 실명·초상 최소화(이니셜·일러스트), 명시적 disclaimer, MVP는 샘플/아키타입 시연 → 상용화 시 기획사 제휴. 리스크 인지·관리 팀에 심사 가점.
독창성 방어 idolsaju·350+ 아이돌 궁합 등 유사 서비스 이미 존재 선례는 오히려 수요 검증(시의성 가점). 차별점 = 여행 전환(스타 고향→KTO) + 외국인·다국어·인바운드 지방분산.

Deep-dive · experiment

바이럴 카드 A/B 설계

공유율은 K를 곱셈으로 키운다 → 몇 %p 상승도 복리. 단, 지금은 진짜 A/B를 돌릴 트래픽이 없음(표본 부족=노이즈). 정직하게 2단계로.

지표 & 계측

  • 1차 공유율(공유/결과조회) · 북극성 K
  • 가드레일: 신고·불만율(미신 백래시), 완료율
  • 필수: 카드별 고유 딥링크(UTM) → 구축 S3/S4

2단계 로드맵

  • Phase 0(트래픽≈0): 타깃 8~12명 카드 3종 "어느 걸 공유?" + painted-door → 기본값 선택 (통계 아님)
  • Phase 1(변형당 ~2–3k 조회): 진짜 A/B. 초기엔 대담한 차이로 ~1k 절약
