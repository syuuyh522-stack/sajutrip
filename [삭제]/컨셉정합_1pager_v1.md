## TL;DR

우리는 **과제 3(K-콘텐츠·아티스트 관광 수도권 편중 + 글로벌 팬덤 지방 방문 불편)**으로 접수했다.
그런데 현 PRD(사주트립)는 **K-콘텐츠·팬덤·다국어를 전부 덜어내** 사실상 과제 2(오버투어리즘 일반)처럼 읽힌다.
→ **"사주 기반 여행지 추천"은 유지하되, 사주와 지방 사이에 'K-콘텐츠 다리'와 '다국어'를 복원**해야 과제 부합이 성립한다.

**제안: 하이브리드(A 아이돌 다리 코어 + B K-콘텐츠 성지 확장) 채택.**

## 1. 왜 지금 이걸 정해야 하나 — 해시태그 테스트

공고: "1차 심사자료 제출 시 **해시태그 연관 기능 설명서** 작성 요청." → 과제 3 해시태그가 심사의 객관적 체크리스트가 된다.

| 과제 3 해시태그 | 현 PRD(사주트립) | 7월 K-Saju Compass |
|---|:--:|:--:|
| #덕질투어 | ❌ K-Star·팬덤 요소 없음 | ✅ 사주 트윈 아이돌 |
| #다국어 | ❌ EN 1개 (KTO 다국어 API 미사용 명시) | ✅ EN·KO·JA·ES |
| #로컬관광 | ✅ 지방 분산 | ✅ |
| #여행플래너 | ✅ 동선 설정 | ✅ |

**현 PRD는 4개 중 2개가 깨짐.** 깨진 둘(#덕질투어·#다국어)이 과제 3을 과제 2와 구분 짓는 핵심.
→ 방치 시 심사 **기획력(30) + 데이터 활용(20)** 직접 타격. 차별화(vs 사주여지도)도 소멸.

## 2. 옵션 비교

세 안 모두 코어는 "사주 → 여행지 추천"으로 동일. 차이는 **사주와 지방을 잇는 다리**.

| | A. 아이돌 다리 (7월 원안) | B. K-콘텐츠 다리 (넓힘) | C. 현 PRD 유지 |
|---|---|---|---|
| 메커니즘 | 사주 → 트윈/궁합 아이돌 → **아이돌 고향·연고 지방** | 사주 오행 → 지방 배정 + **드라마 촬영지·전통문화 성지·아티스트 연고** | 사주 오행 → 부족한 기운 채우는 여행(일반) |
| 과제 3 정합 | ◎ 완전 | ○ 성립 | ✕ (과제 2에 가까움) |
| 바이럴 훅 | ◎ 공유카드 강력 | △ 보통 | △ 약함 |
| 차별화(빈자리) | ◎ 다국어 아이돌+여행 = 무주공산 | ○ | ✕ 사주여지도 영어판 |
| 초상권·법적 리스크 | △ 스타 명식 DB·초상 최소화 필요 ([[saju_기능추가_kstar_v3]]) | ○ 낮음 | ◎ 없음 |
| 구현 부담 | 높음(스타 DB 50명·궁합) | 중 | 낮음 |

## 3. 추천안 — 하이브리드 (A 코어 + B 확장)

- **A를 유입·바이럴 코어로**: "My Saju Twin: [아이돌]" 공유카드 → 아이돌 고향으로 회수 → #덕질투어 충족
- **B를 커버리지 확장으로**: 아이돌 연고가 없는 오행/지역은 K-콘텐츠 성지(촬영지·전통문화)로 보완 → 지방 커버리지·설득력 ↑, 데몬헌터스 트렌드(PRD 배경)와 결 맞음
- **다국어 최소 복원**: 최소 EN+1(중 또는 일). KTO 다국어 관광정보 API 활용 = #다국어 + 데이터활용 점수 동시 확보

**근거**: 과제 3의 두 축(아티스트+팬덤 / 지방 분산)을 동시에 덮고, 심사 4개 항목에 고르게 기여. 리스크는 초상권인데 [[saju_기능추가_kstar_v3]]의 실명·초상 최소화·샘플 시연 방식으로 관리 가능.

## 4. 확정 시 P0 스코프 영향 (현 PRD 대비 변경분)

**추가해야 할 것**
- [ ] 스타 명식 DB (공개 생년월일 50명, 오행 사전계산 + 연고 지방 필드) — [[구축계획_v4]] S3
- [ ] 사주 트윈/궁합 매칭 로직 + 공유카드(딥링크·UTM) — 바이럴 계측용 ([[바이럴카드_ABtest_v6]])
- [ ] KTO **다국어 관광정보 API** 연동 (EN + 1개 언어)
- [ ] 오행 → 지방 매핑 테이블에 **K-콘텐츠 성지 레이어** 추가

**유지**
- 사주 오행 입력·풀이, 장소 추천/동선, 검색/SRP, 어필리에이트 BM, Airtable(데이터 저장)

**재검토**
- 스택: Airtable(현 PRD) vs 서버리스 KTO 프록시(7월안) — 다국어·연관관광지 API 물량 감당 관점에서 결정
- "부족한 기운 채우기" 프레이밍 → "나만의 지방 + 트윈 아이돌" 프레이밍으로 상위 메시지 교체

## 5. 미팅에서 결정할 질문 (여기만 합의되면 스펙 얼림)

1. **다리 방식**: A / B / 하이브리드 중 무엇? (추천: 하이브리드)
2. **K-Star 범위**: 아이돌 몇 명·어떤 IP? 초상권 관리선은? (P0 vs P1)
3. **다국어 범위**: EN only 유지 불가 → EN + 무엇? (중/일)
4. **스택**: Airtable 유지 vs 서버리스 프록시
5. **목표 지표 확정**: 북극성 = "수도권 밖 지방을 여정에 담은 비율" (과제 3 직결) — 채택 여부
6. **오행 태깅 방법론**: 오방색 택소노미 + 수동 vs 규칙 자동 (별도 초안 필요)
